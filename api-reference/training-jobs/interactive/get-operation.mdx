`GET /v1/training/operations/{idempotency_key}`

Send the original key used on a native interactive POST or an encoder job create. Keys are team-scoped; an unknown or inaccessible call returns `not_found`.

An `accepted` receipt means the request was admitted, not that execution succeeded. While admission is still in progress, `job_id`, `future_id` and `future_status` can be null. Once known, use the original future to read its outcome. A stop has no future; encoder creates return their job only.

To retry an uncertain native request, resend the same body, route and key. A different request under the same key returns 422; an in-progress first call returns 409. Use a new key for intentionally new work. Receipt retention/expiry is not a guarantee of this endpoint.

<ParamField header="X-API-Key" type="string" required>
  Fastino API key.
</ParamField>

<ParamField path="idempotency_key" type="string" required>
  Idempotency-Key.
</ParamField>

```json
{

  "status": "accepted",
  "operation": "forward-backward",
  "job_id": "SESSION_ID:train:0",
  "future_id": "FUTURE_ID",
  "future_status": "completed"
}
```

</ResponseExample>
