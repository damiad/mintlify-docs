## Elige un tipo de trabajo

Cada trabajo tiene un `type`:

| Tipo | ¿Quién controla el bucle? | Cómo se inicia |
| --- | --- | --- |
| `config` | Fastino | Envía un dataset y una configuración a `POST /v1/training/jobs`. |
| `interactive` | Tu aplicación | Crea un cliente de entrenamiento mediante el adaptador del SDK compatible. |

Ambos tipos comparten la misma identidad de trabajo. Las lecturas canónicas usan
`GET /v1/training/jobs`, `GET /v1/training/jobs/{job_id}` y
`GET /v1/training/jobs/{job_id}/checkpoints`.

El adaptador de compatibilidad no es un segundo servicio de entrenamiento.
Traduce las llamadas compatibles del SDK en operaciones sobre un trabajo
interactivo de Fastino. Las operaciones del adaptador se omiten
intencionadamente de OpenAPI; no construyas sus rutas HTTP por tu cuenta.

## Ciclo de vida de los trabajos de configuración

Los siguientes estados persistidos describen los trabajos `config` gestionados.
Los trabajos interactivos tienen un comportamiento controlado por el llamante;
no deduzcas su ciclo de vida a partir de esta tabla.

| Estado persistido | Descripción |
| --- | --- |
| `requested` | El trabajo se aceptó y está a la espera de envío o aprovisionamiento. |
| `running` | El entrenamiento está en curso. |
| `complete` | El entrenamiento se completó correctamente. La preparación del artefacto puede continuar. |
| `normalizing` | Fastino está preparando el artefacto entrenado. |
| `artifact_ready` | El artefacto entrenado está listo. |
| `deployed` | El artefacto se ha desplegado. |
| `paused` | El trabajo gestionado está en pausa. |
| `errored` | El entrenamiento, el envío o la preparación del artefacto falló. |
| `stopped` | El trabajo se detuvo conservando los checkpoints existentes. |
| `terminated` | El trabajo se terminó. Los checkpoints se conservan salvo que `delete_checkpoints` sea `true`. |

`normalized_status` proporciona el valor estable para las consultas, incluido
`failed` para un fallo terminal. `status` conserva el valor persistido, como
`errored`.
