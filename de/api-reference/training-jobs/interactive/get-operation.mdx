`GET /v1/training/operations/{idempotency_key}`

Senden Sie den ursprünglichen Schlüssel eines nativen interaktiven POST oder einer Encoder-Job-Erstellung. Schlüssel sind teambezogen; unbekannte oder nicht zugängliche Aufrufe liefern `not_found`.

Ein Beleg mit `accepted` bestätigt die Annahme, nicht die erfolgreiche Ausführung. Während der Annahme können `job_id`, `future_id` und `future_status` null sein. Sobald bekannt, lesen Sie das Ergebnis über das ursprüngliche Future. Stop hat kein Future; Encoder-Erstellungen liefern nur den Job.

Bei ungewissem Ergebnis einer nativen Anfrage wiederholen Sie Body, Route und Schlüssel unverändert. Eine andere Anfrage mit demselben Schlüssel liefert 422; ein laufender Erstaufruf liefert 409. Verwenden Sie für absichtlich neue Arbeit einen neuen Schlüssel. Dieser Endpunkt garantiert keine Aufbewahrungs- oder Ablaufdauer.

<ParamField header="X-API-Key" type="string" required>
  Fastino API key.
</ParamField>

<ParamField path="idempotency_key" type="string" required>
  Idempotency-Key.
</ParamField>

<ResponseExample>

```json
{
  "idempotency_key": "training-step-1",
  "status": "accepted",
  "operation": "forward-backward",
  "job_id": "SESSION_ID:train:0",
  "future_id": "FUTURE_ID",
  "future_status": "completed"
}
```

</ResponseExample>
