Fastino's SDK adapter translates supported client calls into operations on one
interactive Fastino job. Install `tinker==0.33.1` for the documented workflow;
Fastino's contract suite covers both `0.32.0` and `0.33.1`.

| Item | Supported value |
| --- | --- |
| Package | `tinker==0.33.1` |
| Base URL | `https://api.fastino.ai/v1/training/compat/tinker` |
| Authentication | A `fast_sk_` key printed by `TINKER_CREDENTIAL_CMD` |
| Resource identity | One training client is one interactive Fastino job with the same ID |

The SDK adds `/api/v1/{operation}` to the base URL. Adapter routes are hidden
from OpenAPI and the API reference. Users must not construct adapter requests.

## Training and sampling

| SDK method or operation | Fastino mapping | Support |
| --- | --- | --- |
| `create_lora_training_client` | Create an interactive job through the SDK | Supported |
| `copy_weights` | Start an interactive job from an existing checkpoint | Supported |
| `TrainingClient.get_info` | Read the interactive job | Supported |
| `forward` | Run a forward-only operation | Supported |
| `forward_backward` | Run a forward and backward operation | Supported |
| Custom forward/backward operation | Run a supported custom-loss operation | Supported |
| `optim_step` | Apply an optimizer update | Supported |
| `save_state` | Save training state | Supported |
| `save_weights_for_sampler` | Save sampler weights | Supported |
| Load training state | Restore a state checkpoint | Supported |
| Create or get a sampling client | Resolve sampler weights | Supported |
| `SamplingClient.sample` | Sample through the selected checkpoint | Supported |

Keep the SDK method parameter `base_model` unchanged. Query
`ServiceClient.get_server_capabilities()` before selecting a base model or
depending on an optional operation. Capabilities are the source of truth; this
reference does not establish a fixed model catalog, loss catalog, rank, context
window, or per-call limit.

## Futures

| SDK method or operation | Fastino mapping | Support |
| --- | --- | --- |
| Future result/get | Retrieve one asynchronous result | Supported |
| Future cancel | Request cancellation of one future | Supported |
| `retrieve_futures` batch retrieval | None | Not supported |

## Administration

| SDK method or operation | Fastino mapping | Support |
| --- | --- | --- |
| `RestClient` list training runs | List canonical Fastino jobs | Supported |
| `RestClient` get training run | Get a canonical Fastino job | Supported |
| List or get checkpoints | Inspect interactive-job checkpoints | Supported |
| Download or delete checkpoint | Manage an interactive checkpoint | Supported |
| Publish or unpublish checkpoint | Change checkpoint publication | Supported |
| Set or clear checkpoint TTL | Change checkpoint retention | Supported |
| `RestClient.get_current_checkpoint_storage_usage` | Read current checkpoint storage | Supported |
| `RestClient.get_billing_usage` | Read hourly SDK usage events | Supported |

## Adapter-only plumbing

The SDK owns capabilities, sessions, heartbeat, telemetry, identity checks,
token exchange, and usage plumbing. It exchanges the Fastino key printed by
`TINKER_CREDENTIAL_CMD` for a short-lived credential used on later SDK calls.
These are implementation details, not customer-authored HTTP requests.

## Explicitly unsupported

- Batch future retrieval through `retrieve_futures`
- `save_weights_external`
- `external_weights_urls`

Authentication is provided only by a normal Fastino `fast_sk_` key through
`TINKER_CREDENTIAL_CMD`. Credentials beginning with `tml-` are rejected, and
active examples must not set `TINKER_API_KEY`.
